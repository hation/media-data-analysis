# 项目规则 · 抖音数据销售分析

本目录是「抖音搜索数据离线销售分析」项目（MediaCrawler 爬取 + 本地离线分析）。
以下规则对所有涉及本项目的分析/数据处理任务**强制执行**，每次会话开始时自动加载。

## 1. 分析前必读（第一步，不可跳过）

任何与本项目数据分析相关的任务，开始动手前**必须先 Read**：

- `抖音数据销售分析说明.md` —— 数据来源、分析步骤、规则表、产出定义、使用约定（重点读「0. 使用约定」「3.2 爆款识别」「3.3 意向规则表」「3.8 品类规则配置」）
- `analyze.py` —— 确认当前脚本的实际实现与文档一致

**执行分析时必须使用项目级 skill：`analyze-douyin-keyword`（`.trae/skills/analyze-douyin-keyword/SKILL.md`）**，按其五步流程执行（识别关键词 → 规划词典 → 跑脚本 → 提炼新词 → 用户决策重跑）。禁止绕过 skill 自行设计分析流程。

禁止在未读这两份文件的情况下重新"发明"分析逻辑、凭印象执行或修改代码。

## 2. 标准执行流程

1. 数据放入 `input/`（MediaCrawler 导出，命名含 `search_contents_*` / `search_comments_*`；脚本自动取最新文件）。
2. 运行 `python analyze.py`（纯 Python 标准库，离线、无大模型、无第三方依赖）。
3. 产出在 `output/关键词_平台_yyyymmddhhmm/` 批次目录，含 5 个 CSV + `运行摘要.txt`。
4. 跑完**必须对比本批 `运行摘要.txt` 与历史批次**的关键数字（视频/评论数、意向分层、爆款类型）：
   - 数字一致 → 口径未变，结果可用；
   - 数字异常 → 先排查数据或规则变化，确认后再使用，不得静默忽略。

## 3. 规则变更纪律（防止漂移）

若需调整分析规则（意图词、阈值、占比定义、输出格式等），必须**三处同步**：

- 改 `analyze.py`（唯一执行入口）
- 同步更新 `抖音数据销售分析说明.md`（规范文档）
- 跑一次生成新批次作为新基线，再对比旧批次说明变化原因

禁止只改其中一处。脚本与文档不一致视为未完成。

## 4. 数据与产出边界

- 昵称已脱敏，定位用户以 `user_homepage` 或 `creator_hash` 为准。
- 意向规则表可按品类词（内存/固态等）微调，弱意图（规格/价格）名单需人工复核。
- 每次运行必须生成新批次目录，禁止覆盖旧批次。
