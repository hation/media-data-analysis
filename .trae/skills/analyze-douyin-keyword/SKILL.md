# 分析抖音关键词数据

对 MediaCrawler 导出的抖音搜索数据做离线销售分析。分析对象是 `input/` 目录下成对的 `search_contents` 与 `search_comments` CSV（同一关键词、同一平台）。规范依据见项目根目录 `抖音数据销售分析说明.md`。

## 五步流程

### 第 1 步 识别关键词（自动）

从文件名解析关键词与平台。命名规律：`search_contents|search_comments_时间戳_关键词_平台.csv`，按 `_` 分段，**倒数第二段是关键词、倒数第一段是平台**（如 `search_contents_2026-10-21-17-47_硬盘_douyin.csv` → 关键词=`硬盘`、平台=`douyin`）。文件名解析失败时，读 CSV 的 `source_keyword` 字段兜底。关键词即 `config/品类规则.json` 中「品类」的 key。

**数据核对（不可跳过）**：解析出关键词后，先确认 `input/` 里确实存在该关键词的成对文件（`search_contents_*_<关键词>_*.csv` 与 `search_comments_*_<关键词>_*.csv`）。若数据缺失或关键词与用户所说不一致，**先向用户报告并确认意图**，禁止直接跑脚本（否则会静默分析成别的关键词）。

### 第 2 步 规划词典（大模型介入）

打开 `config/品类规则.json`：

- 关键词已存在 → **直接复用，不做任何修改**。
- 关键词不存在 → 按关键词规划三类词（需求词 / 规格词 / 统计词），参考已有相近品类，写入 config，并向用户说明新增了什么、为什么。
- 只允许改 config。**禁止改动 analyze.py 的分析规则逻辑**。

### 第 3 步 运行脚本（纯脚本）

运行 `python analyze.py`（纯标准库、离线、无需大模型）。产出 `output/关键词_平台_时间戳/` 批次目录（5 个 CSV + 运行摘要.txt）。**禁止用大模型替代脚本计算**；结果数字以脚本为准。

### 第 4 步 提炼遗漏词（大模型介入）

读本批视频的 title/desc 与评论内容，对照 config 当前词典，找出漏掉的词，**分类列出新增词清单**，并提醒用户对这批新词选择处理方式（三选一，本步不写入 config）：

- **入 config 不重跑** —— 新词补进词典，本次批次保持不变，后续分析自动生效
- **入 config 并重跑** —— 补进词典，并立即重跑生成新批次
- **直接结束** —— 忽略新词，不写入 config

**提炼标准（只收购买信号增强词）**：

| 类别 | 收 | 不收 |
| --- | --- | --- |
| 规格限定词 | 容量单位（12t/24t）、存储技术（叠瓦/tlc/qlc/cmr/smr/sas/raid）、接口/主控/缓存 | 描述性词（通电/噪音/发热/健康度） |
| 品牌词 | 硬盘品牌名（东芝/梵想/佰维/雷克沙/长江存储/英特尔…） | 泛称（"硬盘"本身） |
| 需求动作词 | 加装/换固态/拆机 | 宽泛场景词（服务器/nas）、二手盘话题词（清零/翻新） |

频率只作为候选线索，**最终以"该词是否增强购买意向判定"为准**；对每个候选词标注「建议入 / 不建议入」及理由。

### 第 5 步 按用户选择执行

根据用户在三分类中的选择执行（重跑环节无大模型介入）：

- **入 config 不重跑** → 把新词补进 `config/品类规则.json`，同步更新说明文档「3.8」，本批结果不变，流程结束。
- **入 config 并重跑** → 补进 config + 同步文档，再**直接运行 analyze.py**（纯脚本），生成新批次，并与上一批 `运行摘要.txt` 对比关键数字后汇报。
- **直接结束** → 不写 config，流程结束。

## 硬约束

- 大模型只出现在第 2 步（规划词典）和第 4 步（提炼新词）；第 3 步与第 5 步的重跑都是纯脚本执行。
- 新增词必须分类列出并让用户在「入 config 不重跑 / 入 config 并重跑 / 直接结束」三选一，**禁止擅自决定或默认重跑**。
- 提炼遗漏词必须按第 4 步提炼标准过滤（只收购买信号增强词），**禁止仅按出现频率收词**。
- 改动 config 必须同步更新说明文档的「3.8 品类规则配置」，保持脚本、文档、配置三者一致（项目规则第 3 条）。
- 每次运行生成新批次目录，禁止覆盖旧批次。
- 分析前确认已读说明文档（项目规则第 1 条）与本 SKILL。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 词典写死在 analyze.py | 词典全部在 config/品类规则.json，脚本按关键词自动加载 |
| 新关键词直接跑，规格/品牌词为空 | 第 2 步先规划词典写入 config，否则脚本会用通用词并警告 |
| 提炼出新词后擅自补进 config 或擅自重跑 | 先列出清单让用户三选一（入config不重跑 / 入config并重跑 / 直接结束），按用户选择执行 |
| 用大模型"算"意向用户/爆款排序 | 全部交给 analyze.py，大模型只做词典规划与提炼 |
