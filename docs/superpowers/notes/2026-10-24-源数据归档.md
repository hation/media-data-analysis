## 需求来源
`input/` 堆积多个关键词历史数据，易误读旧数据、难以回溯某次分析的原始数据。用户选择方案 C：批次目录内留一份副本（自包含可追溯）+ 源数据移出 input 归档，且归档目录指定为与 input 平级的项目根 `archive/`（非 input/archive）。

## 实现内容
- `analyze.py` 新增「7. 源数据归档」区块（在运行摘要写出后、收尾打印前）：
  - 顶部捕获 `_comments_path = find_csv("search_comments")`，运行摘要与归档循环统一复用（避免二次 find_csv 归档错文件、保证评论文件缺失时警告跳过而非崩溃）；

## 技术债（遗留，待后续）
1. `_comments_path` 在 L91 捕获晚于 L86 COMMENTS 数据读取：若两行之间 input 恰好出现更新的评论文件，归档路径可能与实际读取文件不一致——与 `_contents_path` 既有模式一致，概率极低，未处理。
2. 源文件缺失警告分支无自动化测试（正常流程不可达，代码审读确认）。
3. `ARCHIVE_DIR` 定义在脚本中部而非顶部「路径与目录」区（计划片段如此，组织略割裂，未改）。

## Rulings（执行中的判断）
- 归档目录：项目根 `archive/`（用户指定，与 input 平级，非 input/archive）。
- 批次内副本放 `源数据/` 子目录（与结果 CSV 区分）。
- 全量重跑验证时 input 最新已是用户新导入的 DDR5 数据，故本次真实运行归档的是 DDR5 一对（SSD企业级硬盘 基线对比不适用）；归档机制正确性不受影响。
- 执行方式沿用用户固定设置 Subagent-driven development。
